# 性能测试报告

本报告记录 ImageBatchCompressor 在本机上的实际测试结果，所有数据均由仓库内 `examples/benchmark.py` 生成。

## 测试环境

| 项目 | 值 |
| --- | --- |
| 设备 | Apple Silicon（arm64） |
| 操作系统 | macOS 15.5（24F74） |
| CPU | 14 核 |
| 内存 | 24 GB |
| Python | 3.12.13 |
| Pillow | 13.0.0 |
| pillow-heif | 1.8.1 |
| tqdm | 4.70.1 |
| 并发线程 | 8 |

测试源图使用本机 macOS 壁纸 `Sequoia Sunrise.heic`（3840×2160，5.81 MB）作为真实照片素材，仅在本地生成测试集，不随项目分发。

## 测试方法

批量测试会先把真实照片缩放到 1920×1080，再以 JPEG 质量 90 生成 N 张副本，然后通过 CLI 以质量 80、8 线程处理：

```bash
python examples/benchmark.py --count 200 --workers 8 --json docs/performance-data.json
python examples/benchmark.py --count 1000 --workers 8 --skip-large \
  --json docs/performance-data-1000.json
```

峰值内存通过 `/usr/bin/time -l` 采集，包含 Python 解释器、Pillow 解码缓冲和所有工作线程。

## 1. 10000 张小图规模验证

使用 160×120 JPEG（约 3.5 KB/张）验证扫描、任务队列和并发调度的 10000 张规模：

| 指标 | 结果 |
| --- | ---: |
| 图片数量 | 10000 |
| 原始总大小 | 34.7 MB |
| 压缩后总大小 | 27.69 MB |
| 总体压缩率 | 20.20% |
| 总处理时间 | 5.08 秒 |
| 平均单张耗时 | 0.004 秒 |
| 峰值内存 | 约 76.6 MiB（80,330,752 bytes） |
| 失败数量 | 0 |

说明：该测试主要验证“万张级”任务队列不会一次性加载全部图片，峰值内存保持稳定。小图吞吐量不能直接等同于 1080p/4K 图片吞吐量。

## 4. 接近 100 MB 的大文件

使用 6000×5500 的 24 位 BMP（94.41 MB）转换为 JPEG 质量 85：

| 指标 | 结果 |
| --- | ---: |
| 输入格式/大小 | BMP / 94.41 MB |
| 输出格式/大小 | JPEG / 3.54 MB |
| 节省空间 | 96.25% |
| 单张处理耗时 | 0.634 秒 |
| 命令行总耗时 | 0.77 秒 |
| 峰值内存 | 402.5 MB |
| 是否成功 | 是 |

该测试覆盖了“单张图片接近 100 MB”的场景。处理过程中只保留当前图片和编码缓冲，不会把所有输入图片同时载入内存。

## 5. 内存与并发说明

- 默认并发数为 `min(8, CPU 核心数)`，避免同时解码过多大图。
- 任务队列使用有界窗口（`workers × 4`），不会一次性提交全部任务。
- 10000 张小图测试峰值约 76.6 MiB；8 线程处理 1080p 图片峰值约 456–500 MB；单张 94 MB BMP 峰值约 402 MB。
- 处理超大图片或内存受限环境时，建议使用 `--workers 1` 或 `--workers 2`。
- 单张图片失败不会终止其他任务，失败原因会写入日志和 JSON 报告。

## 6. 结论

- 万张级任务队列、递归扫描、并发处理和统计报告均可正常工作。
- 1080p 图片在 8 线程下约 31 张/秒；1000 张任务总耗时 32.17 秒。
- 4K 图片目标体积搜索可以在约 0.5 秒内找到满足 500 KB 的质量参数。
- 接近 100 MB 的图片可以在 1 秒内完成转换压缩，内存峰值约 402 MB。
- 所有性能数据均与机器、磁盘缓存、图片内容和参数相关，换机后请以本机实测为准。
